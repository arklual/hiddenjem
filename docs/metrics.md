# Hiddenjem — оценка качества

Три замера: решение «слабый сигнал / не слабый» на размеченном датасете кейса, модель внешних
признаков на отложенной выборке и качество итоговой выдачи ТОП-15 по критериям жюри.

## 1. Размеченный датасет кейса: Precision, Recall, F1

| Метрика | Значение |
|---|---|
| Precision | **0,892** |
| Recall | **0,740** |
| F1 | **0,809** |
| Accuracy | 0,799 |

|  | решено «слабый сигнал» | решено «не слабый» |
|---|---|---|
| размечено «слабый сигнал» | 74 | 26 |
| отрицательный контроль | 9 | 65 |

**Данные.**
- Положительный класс — 100 слабых сигналов из датасета кейса
  (`100_слабых_технологических_сигналов_сентябрь_2026.xlsx`).
- Отрицательный контроль — 74 технологии, заведомо не являющиеся слабыми сигналами
  (`fixtures/validation/negatives.json`):
  - 48 зрелых (облачные вычисления, Kubernetes и т. п.);
  - 14 хайповых;
  - 12 отраслевых стандартов.

**Как считается.**
- Для каждой строки строится поисковая формулировка. По ней из OpenAlex, arXiv, GitHub,
  Hacker News и Википедии собираются ряды по годам.
- Решение выносится по абсолютным порогам ([technical.md](technical.md), раздел 5).
- Формулировки и ответы источников сохранены в `fixtures/validation/`, поэтому прогон
  воспроизводим. Повторный прогон 29.09 на текущем коде дал те же числа, что замер 18.09.

**Ошибки.**
- 26 пропущенных сигналов: в основном у технологии слишком мало следов в открытых API (0–1 вид
  источников при требуемых двух) или первое упоминание старше окна зарождения. Пример — «федеративное
  обучение» в формулировке датасета: 46 тыс. работ за три года.
- 9 ложных срабатываний: зрелые технологии и стандарты с умеренным числом работ и растущей
  динамикой (vector database, zero trust, ISO 20022).

Полная таблица с решением и объяснением по каждой строке — [dataset-validation.md](dataset-validation.md).

**Воспроизвести:**

```bash
make venv
make validate-dataset DATASET=/путь/к/100_слабых_технологических_сигналов_сентябрь_2026.xlsx
# отчёт: build/reports/dataset-validation-current.md
```

Логистическая регрессия по 16 признакам (OpenAlex, Hacker News, Википедия, корпус), артефакт
`signals-model.json` версии `2026-09-20.1`.

| Метрика | Значение |
|---|---|
| ROC-AUC на отложенной выборке | **0,724** |
| Размер отложенной выборки | 248 |

Модель даёт половину балла темы; вторую половину — методология зарождения по корпусу
([technical.md](technical.md), раздел 3.4).

## 3. Качество выдачи ТОП-N по критериям жюри

Отчёты, построенные системой на демонстрационном стенде 29.09 в быстром режиме, оценены вслепую:

- каждую позицию независимо оценивали три LLM-эксперта по четырём критериям жюри (технология,
  по теме, ранняя стадия, подтверждение источниками 2024–2026 годов);
- решение — большинством голосов;
- эксперты видели только карточку (название, определение, пример, источники) и не знали, откуда
  взялась тема.

| Направление | «Да» | Доля |
|---|---|---|
| Юридические технологии | 13 из 15 | 87 % |
| Квантовые технологии¹ | 12 из 15 | 80 % |
| Нейроинтерфейсы | 11 из 15 | 73 % |
| Технологии для недвижимости | 9 из 15 | 60 % |
| Умные города | 6 из 10 | 60 % |
| **Всего** | **51 из 70** | **73 %** |

¹ Отчёт собран, когда API языковой модели не отвечал. Экспертная стадия не проводилась: выдача
построена правилами и разметкой веб-корпуса.

**По происхождению темы** (в отчётах, где оно известно):

| Откуда тема | «Да» |
|---|---|
| Сигналы веб-корпуса, заранее размеченные через LLM по критериям жюри | 35 из 38 (92 %) |
| Темы, найденные на лету в собранном корпусе | 3 из 17 (18 %) |

**Выводы.**
- Качество выдачи держится на заранее размеченном веб-корпусе. Темы, выделенные на лету, чаще
  оказываются обрывками фраз или мейнстримом, и экспертная стадия отсекает их не полностью.
- Поэтому отчёт скорее станет короче, чем добьёт ТОП непроверенными темами.
- Разметка корпуса и оценка выполнены LLM по одним и тем же критериям. Эта оценка не независима
  и, вероятно, выше, чем дало бы жюри. Шум самой разметки — около 15 %: две независимые разметки
  одних и тех же позиций совпадают на 85 %.

## 4. Время анализа

Быстрый режим на стенде (8 CPU, 23 ГБ ОЗУ) — 7–15 минут на направление, включая сбор из всех
источников и работу агента-исследователя. Качественный режим дольше: агенту отводится до
20 минут.
