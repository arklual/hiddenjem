# Перекрёстный словарь направлений: формулировка аналитика → предметные метки корпуса.
#
# Зачем он существует
# ───────────────────
# Отнесение темы к направлению держится на предметных кодах источников (методология §12): arXiv
# ставит категории, OpenAlex — концепты, патентные ведомства — классы CPC, GitHub — темы
# репозитория. Все они на английском. Аналитик набирает направление по-русски. Стем «интеллект» не
# совпадает со стемом «intelligence» ни при каком алгоритме стемминга, поэтому без этого файла ни
# один документ не относится к направлению — и отчёт перестаёт зависеть от того, что спросили: три
# разных русских направления дают один и тот же список тем.
#
# Почему словарь, а не перевод
# ────────────────────────────
# Машинный перевод недетерминирован и внешний, а ADR-0015 требует воспроизводимости: один и тот же
# запрос обязан давать один и тот же отчёт. Курируемый словарь — обычная практика tech mining
# (crosswalk к контролируемому словарю), он проверяем, правится вручную и виден в ревью.
#
# Формат
# ──────
#   формулировка аналитика = целевая метка | другая целевая метка
#
# Слева — как пишет аналитик; справа — метка предметного словаря корпуса. Обе стороны стеммируются
# тем же алгоритмом, что и остальной конвейер, поэтому падежи и число значения не имеют:
# «квантовых вычислений» и «квантовые вычисления» дают один ключ.
#
# ВАЖНО: правая часть сопоставляется с меткой документа как непрерывная фраза по границам слов.
# Не по отдельным словам — и не обязательно с меткой целиком. Разница существенна в обе стороны:
#
#   • не по словам: пока сопоставление шло по словам, «материаловедение» через слово `science`
#     забирало 355 документов из 1244 — всё, что размечено `Computer science`, — а «компьютерное
#     зрение» через `computer` забирало 216 документов и ни одного по компьютерному зрению;
#   • не целиком: цель `cryptography` обязана забирать `Quantum cryptography` и `Public-key
#     cryptography` — это криптография, названная точнее.
#
# Отсюда ловушка, на которой мы уже попались. Однословная цель — это фраза из одного слова, и она
# совпадает с любой меткой, где это слово стоит. Цель `security` забирала `Food security`,
# `Energy security`, `National security` и `Security analysis` (в OpenAlex это финансовый анализ
# ценных бумаг) — 32 документа корпуса, не имеющих отношения к защите информации.
#
# Отличить `Quantum cryptography` (уточнение) от `Food security` (омоним) по строению фразы
# нельзя: обе — «слово + наша цель». Различает только смысл, а смысл живёт здесь, в словаре.
# Поэтому правило такое: однословную цель писать можно, только если само слово называет предмет
# независимо от того, что стоит рядом. `cryptography` — называет. `security`, `science`,
# `computer`, `engineering`, `systems`, `analysis` — не называют: их предмет задаёт определение
# слева от них. Для таких пишите метку целиком, столько строк, сколько нужно.
#
# Правило пополнения: справа пишется то, что ДЕЙСТВИТЕЛЬНО встречается в метках источников —
# включая коды (`cs.LG`, `quant-ph`, `q-bio.GN`, `cond-mat.mtrl-sci`). Коды покрывают препринты, а
# препринт — самый ранний сигнал, ради которого продукт существует: без кодов четыре пятых корпуса
# arXiv не относится ни к какому направлению. Метка, которой в корпусе нет, ничего не сломает, но и
# не поможет.
